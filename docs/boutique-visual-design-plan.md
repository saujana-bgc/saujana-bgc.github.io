# Boutique visual design plan

Make Saujana feel like a thoughtfully hosted local games club. Use gathering photography and existing illustrations to show what it’s like to sit at the table. Give event dates, game covers, scores and stories a clear visual order so the same care carries through to practical pages.

The current site already has a distinctive wordmark, Playfair Display headings, warm paper backgrounds, green accents and community artwork. The Home collage repeats the invitation in text embedded in the image. Collection places search and filters on either side of a featured game, while its title takes a large share of the first screen. The calculator already brings entry controls high on mobile, though several labels are small. Start with those differences in mind and build on the [visual polish plan](visual-polish-and-predictability-plan.md) and [responsive text guidance](responsive-text-wrapping-plan.md).

The review used current Vue and CSS source and above-the-fold screenshots from the local static export at 390 and 1440 CSS px. Signed-in organiser screens were reviewed from source. Populated and transactional states still need fixture-based visual review during implementation.

## Shared visual direction

- **Colour.** Keep warm paper (`#F7F5EF`), near-white (`#FFFEFA`) and deep Saujana green (`#354C3E`). Use brass (`#8A6A3E`) for fine rules and occasional emphasis. Use a dark green panel sparingly where it can frame existing artwork. Give Clocktower a restrained wine accent and Riichi Open a brass accent. Use the shared semantic colours and text labels for status feedback.
- **Type.** Keep the self-hosted Playfair Display for public titles and select editorial headings. Use the existing sans serif for body copy, navigation, forms and tables. Start at 16 px for body copy and 14 px for recurring controls and essential metadata. Reserve smaller type for secondary notes. Use tabular figures for dates, times, scores and standings where alignment helps scanning.
- **Composition.** Use the existing reading, standard and wide content widths with shared gutters. Use a photo-led or illustrated introduction on discovery pages, a short left-aligned heading and immediate controls on browsing and utility pages, and a clear text column on reference pages. Leave supporting copy on the page surface. Use fine borders for panels that group interactive content and stronger elevation for dialogs and drawers.
- **Images.** Lead with a single strong gathering image on Home. Review the existing collage beside a single permission-cleared photo and use the photo if it crops well at both sizes. Keep illustration for activity and Birthday Club pages. Align crop ratios within each image family, show box covers in consistent square frames, and present tournament posters at their portrait ratio. Keep responsive sources, intrinsic dimensions and lazy loading below the fold.
- **Navigation and controls.** Align the wordmark, menus and footer to the page grid. Give the active route a clear indicator on desktop and mobile, and move visitor counts and update information into a quiet footer row. Use a solid green primary action, an outlined secondary action and underlined text links where appropriate. Standardise control height, focus, selected states and nearby feedback through the existing Nuxt UI and CSS patterns. Keep compact scoring inputs suited to use at the table.

## Implementation order

1. **Prototype the shared system.** Start with Home, Gatherings and Riichi Calculator at 390 and 1440 CSS px. These cover an editorial page, an event and sign-up page, and a dense utility. Compare title scale, action prominence and image crop before committing shared variants to [main.css](../app/assets/css/main.css), [app.config.ts](../app.config.ts) and the [public layout](../app/layouts/default.vue).
2. **Extend the public pages.** Apply the imagery and editorial layout to Board Games, Riichi Mahjong, Clocktower and Birthday Club. Reuse [ActivityOverviewFeature](../app/components/ActivityOverviewFeature.vue) where the content fits. Carry the chosen toolbar, list, table and reading styles into Collection, Play History, Recaps, League, Open and Rules. Keep page-local styles for controls that serve a specific task.
3. **Finish organiser pages and fallbacks.** Apply the same palette, type, actions and feedback to the [organiser layout](../app/layouts/admin.vue) and its modules. Finish the 404 and check both legacy redirects. Record the approved patterns in [CODEX.md](../CODEX.md) once the rollout is verified.

## Release checks

- Compare every route at 390 and 1440 CSS px with before-and-after screenshots. Check 320 px, both sides of the navigation breakpoint and native 200% zoom. Run `npm run verify:responsive` against the generated site. Verify that tables with wide data scroll within their own region.
- Check keyboard focus, drawer and dialog focus return, sticky-header offsets, reduced motion, screen-reader status announcements and WCAG 2.2 AA contrast. On phones, confirm that the next gathering, Collection search, calculator mode selector and Open standings or registration action are visible near the top of their pages.
- Review populated, loading, empty and error states. Use fixture data for sign-up, payment and receipt recovery, scoring, and organiser save and publish actions. Verify game-list scroll position, rules deep links, spoiler controls and the calculator result panel with the phone keyboard open.
- Compare transferred image bytes and layout shift on Home before and after. Run `npm test`, `npm run typecheck` and generated-site SEO checks. Confirm public canonicals, organiser indexing rules and legacy redirects.
