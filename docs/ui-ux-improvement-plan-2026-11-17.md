# Saujana UI and UX improvement plan

17 November 2026 · Deployed site review and local source at `da88c02`

Start with the path to attending a gathering. Home and Clocktower both linked to the correct 21 November event. The next screen made the same details harder to read and dropped the cost from view when sign-up opened. Fixing that handoff gives visitors a clearer path using the site's existing design.

## Implementation order

1. **Put event facts and sign-up together.** Use one visible heading and a short facts block in every event card, with date, time, venue, Directions and the appropriate next action. Make Sign up the filled action for an open local RSVP. Show an external RSVP and its destination where applicable, and an explicit closed state where people can no longer sign up. Keep the flyer as a labelled preview with a full-size link. On phones, place the preview after the facts and registration block. On desktop, try a side-by-side layout when there is room. Keep the curated description and attendee list below the action.
2. **Make sign-up an inline part of the event card.** Expand the form immediately below the event facts. Keep the event name, applicable venue spend terms and public-list disclosure visible through submission. Keep Name required and the existing optional fields behind their disclosure. Place confirmation and retry near the form. Keep entered values on error, keep focus on Name when opening and return it to the trigger on cancel. Make the saved confirmation easy to find before offering “Add another name”.
3. **Make event links survive the date change.** Resolve the existing `#gathering-*` URL to its event after load. On a past date open Recent and reveal the requested event, including a directly linked older event outside the five-entry list when available. Scroll and focus the target below the sticky header. Give an unavailable event a short explanation and a route to current dates. Test the boundary in Kuala Lumpur and both direct navigation and browser Back.
4. **Shorten the path from Home to an event.** Keep “Find a gathering” prominent and add one short line of beginner reassurance in live text. Prototype a compact next-event panel before the large image on phones. Preserve the event handoff from Home and Clocktower and use the same order and date formatting for the facts they share. Compare the existing hero with a single gathering photo using the same layout and responsive image sizes. The current hero already has responsive variants of roughly 53 KB and 115 KB, so the image change is a design choice. Give Recent compact, dated rows with optional artwork inside each disclosure.
5. **Polish returning-member routes in focused passes.** Give Riichi Open a stable loading panel until the event stage is known on an unqualified visit. Open Standings for completed events and keep explicit tab links and a discoverable route to existing registration and receipt recovery. On Collection and Play History, align count, reset and retry placement. In Collection, make it clear when an action clears filters as well as search. Preserve the dated session view and virtual game grid. Keep the League and Calculator layouts compact and verify their important actions against realistic data before rearranging them.

## Acceptance checks

- At 320, 390 and 1440 px, someone can read the event title, date, time, venue and applicable minimum spend, then find Directions and the relevant RSVP without opening an image. On the initial phone view reached by the event link, the core facts and action are visible below the sticky header. A failed flyer download leaves the same information and actions in place.
- Try the Home and Clocktower links against the same event. Cover a regular gathering, a Clocktower gathering, an external RSVP, a closed or past event, a missing event and an unavailable calendar. Confirm date rollover, keyboard focus, browser Back and 200% browser zoom.
- With test data, complete local sign-up once using only Name and once with optional details. Check cancellation, validation, a failed request, retry and success. Verify that the public-list disclosure stays beside the form and the screen reader announces error and confirmation. Check Birthday Club's two greeting choices before changing any shared form styles.
- Verify Collection and Play History for no results, reset and retry. Verify Riichi Open on cold load, explicit tabs and receipt recovery. Spot-check the League season picker, both Calculator modes and reduced-motion navigation. Run the normal test and generated-site verification commands before release.
- Ask a few people unfamiliar with Saujana to find the next date, explain where to go and what they need to spend if applicable, and start signing up on a phone. Note where they pause or open the flyer for information that should already be on screen.
