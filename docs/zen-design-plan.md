# Zen design plan for Saujana

Apply Zen as a design direction for the public site. Give visitors room to read, make the next step easy to find, and reveal supporting detail where it becomes useful. Saujana should feel like a welcoming board game community, with real people, lively photos and direct language.

The existing design gives us a starting point. Warm paper, deep green, Playfair Display and local community photos already suit the direction. The biggest opportunities are the competing links around the home hero, the visual weight of event and archive cards, and the amount of information competing with the main task on dense pages.

## Shared design decisions

| Area | Proposed direction |
| --- | --- |
| Colour | Use the existing paper `#F7F5EF`, off-white `#FFFEFA`, ink `#393D35` and green `#354C3E`. Use green for the main action and gold `#8A6A3E` sparingly for accents. Give warnings, errors, selected controls and successful submissions clear text and suitable contrast. Let Clocktower and Riichi Open use their own event accents. |
| Type | Keep locally hosted Playfair Display for page titles and selected editorial headings. Use the existing system sans-serif for body text, labels and controls. Start with 16–18 px for prose, around 1.6 line height and a reading width of roughly 55–68 characters. Keep titles in sentence case and use plain labels for forms and filters. |
| Space | Build from the existing 4–40 px scale. Start with 16–20 px mobile gutters and 24–32 px on desktop, 12–16 px between related items and 32–48 px between sections on mobile. Try up to 64 px between editorial sections on desktop. Keep filters, standings and tile controls compact enough to use at the table. |
| Surfaces | Use spacing and thin rules to separate content. Reserve enclosed surfaces for distinct objects such as a gathering, a game detail, a form or a scoring result. Use the existing subtle shadow where elevation helps identify an overlay or floating element. |
| Actions | Give each decision area one visually dominant action. Use understated links for supporting routes and a clear selected state for tabs and filters. Put contact links where questions arise, with a consistent footer fallback. |
| Images | Use the existing Saujana photos to show what joining feels like. Let game covers and event artwork carry their own character. Keep practical facts in readable HTML alongside imagery. Set image dimensions and load secondary photos lazily. |
| Motion | Render essential content in place as soon as it is available. Remove staggered reveals from the main signup, browse and scoring flows. Use brief interaction feedback and static loading placeholders. Honour reduced-motion preferences, including for programmatic scrolling. |

Use `assets/css/main.css` for semantic colours, type and spacing and `app.config.ts` for shared Nuxt UI control variants. Apply them first through `layouts/default.vue` and the pilot pages. Verify shared changes against `layouts/admin.vue` and the event themes before broadening their use. Reuse an existing pattern until a second page demonstrates the need for a shared component.

## Remaining work by page

The Home pilot changed the spacing and surfaces. Finish the public rollout in the order below. Each item identifies what to remove or move, where the information belongs, and what to check after the change.

### 1. Shared layout, Home and Gatherings

- **Shared layout.** The footer now links directly to Gatherings, Collection, Riichi League and Clocktower. Move the general WhatsApp action into the footer and use the in-page contact links for arrival help, private reporting and tournament recovery. Apply the menu changes below first. [Public layout](../layouts/default.vue)
- **Home.** Keep **Find a gathering** and **Plan your first visit** in the hero. Remove the extra **See what we play** shortcut and let the existing section follow the next-gathering band. Move the reassurance for people arriving alone into **Your first gathering** and remove the duplicate “ask around” and WhatsApp paragraph below the pillars. Give the hero and the next-gathering band different jobs. The hero goes to the full calendar and the band links directly to the named event when available. Keep the conduct and private reporting link with **Respect at the table**. [Home](../pages/index.vue)
- **Gatherings.** Move Upcoming and Past above the first-visit disclosure in the template and remove the CSS ordering rules that supported the old layout. Render the event name, date, time, venue and directions in one facts block for events with or without an image. Use a compact summary for collapsed past events. Keep the attendance count in the disclosure summary and remove its duplicate stat tile. Keep the applicable minimum spend before signup, with a short reminder beside editable spend. Remove the minimum-spend stat tile and trim the repeated amount from the guide and notice where the form already displays it. Keep auto-save instructions, separate-row guidance and event-specific terms, including external RSVP requirements. Verify past expansion, deep links, read-only and editable attendance, and signup when the calendar is populated, empty or unavailable. [Gatherings](../pages/gatherings.vue)

#### Public menus

- Use the linked Saujana wordmark as the way home. Give the header five items in this order. **Gatherings** links directly to the calendar. **Board games** contains Collection and Play History. **Riichi mahjong** contains Riichi League, Riichi Calculator and Riichi Open I. **Clocktower** and **Birthday Club** link directly to their pages.
- Define one set of public menu destinations for desktop and mobile. Home’s community cards can keep their contextual invitations. Put the Clocktower first-game shortcut on its page and in the Home card. Match the active group from its own page routes so Gatherings lights up only the Gatherings link. Show the current page visibly and mark it with `aria-current="page"`.
- Keep dropdowns for the two groups on desktop. In the mobile drawer, show their two and three links under static headings so every destination takes one tap after opening the drawer. Use one labelled navigation landmark per menu. Give the hamburger a visible **Menu** label and let the drawer manage its open state and Escape handling. Check click, keyboard activation, focus return on dismissal and access to every link at narrow widths and with larger text.

The virtual grid uses fixed card heights, so update the row-height assumptions together with the CSS if cards get shorter. Check the first and last rows at every column breakpoint. [Collection](../pages/collection.vue)
- **Play History.** Put game search directly under the heading and move the Clocktower cross-link below the results. Keep one results announcement and let dates organise each group. Check the game reveal, search recovery and keyboard pagination. [Play History](../pages/playlog.vue)

Replace the success kicker, decorative heading and thank-you paragraph with one confirmation heading and a short line about the saved preference if needed. Keep the add-another action. ### 3. Riichi League, Calculator and Open I

- **Riichi League.** Remove “One more hand?” and “Season table”. Bring the season selector, current season dates and status together. Explain how the best daily results count beside Standings and remove the repeated best-results figure from the season summary. Keep the placement-point tables and full rules link. Use one visually prominent score-entry action when entry is available. Keep the weekly results jump if it saves a long scroll on mobile. Check season switching, standings, weekly results and score entry. [Riichi League](../pages/riichi-league.vue)

Keep the next action near the relevant input and show the payment once at the top of the result, with a per-player breakdown where needed. Replace the near-identical “Special circumstances” and “Special win circumstances” labels with a heading for the group and a specific disclosure label such as **Special win conditions**. Audit the result panel’s incomplete branches against its ready-only visibility, the separate guidance elsewhere and existing tests before deleting markup. Check both entry modes, the tutorial, undo, the score breakdown and scrolling on a short phone viewport. [Riichi Calculator](../pages/riichi-calculator.vue)

Keep the status bar for the public event state and give the registration panel one specific explanation and action per state. Merge the two closed-registration explanations. For completed submissions, use the confirmation heading for the payment state and the body for the next step. Remove a badge where it repeats the heading within the same panel. Keep expiry, receipt recovery, clarification, payment exceptions and certified results explicit. Check the full state flow with sample data before releasing changes to the event page. [Riichi Open I](../pages/riichi-open/index.vue)

## CSS and motion cleanup during implementation

- Start with the Gatherings .tabs, .tab, .first-time-panel and .event-card rules. Earlier gradients, shadows and decorative borders are overridden later in the same file. Merge the effective declarations and retain intentional breakpoint changes. Apply the same check to the Birthday Club .birthday-card and the League .season-card.
- Use the shared colour, spacing and focus tokens for matching controls. Keep dense tile entry and the event themes scoped to their pages. Compare computed styles at mobile and desktop widths before deleting an older rule.
- Drop staggered entry effects from Gatherings event cards and Collection browse controls as each page is revised. Preserve loading announcements and focus on deep-linked or newly revealed content. Check explicitly requested smooth scrolling in Gatherings and Riichi Open against the reduced-motion preference.

The organiser screens remain an optional follow-up. The public Birthday Club review includes its legacy redirect.


## Review before publishing

- Check 320 px, 390 px, tablet and desktop widths, plus 200% text resizing. Check long event names, dense controls, sticky navigation, short viewports and overlays. Use 44 × 44 CSS px as a Saujana design target for standalone touch controls where practical. Check WCAG 2.2 AA requirements separately, including reflow, visible and unobscured focus, target size, and minimum text contrast of 4.5:1 for normal text and 3:1 for large text. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- Follow keyboard focus from the skip link through navigation and the primary task. Check focus return from menus and dialogs, anchors beneath the sticky header, announcements for loading or error states, and the system reduced-motion setting. Check the prerendered content before hydration.
- Try three tasks on a phone with someone unfamiliar with the site if available. Ask them to find where and when the next gathering happens, find a game in the collection, and locate the payment for a completed riichi hand. Record completion, wrong turns and requests for help. Revise any area where the next action is unclear.
- Run `npm test` and `npm run generate`, which includes SEO verification and regenerates `public/version.json`. Review the static export and compare it with the baseline for layout shifts and unexpected asset growth. Use local or staging data for submissions. If checking the live site, opt out of visitor counting with `?skipStats=1` as described in `CODEX.md`.
