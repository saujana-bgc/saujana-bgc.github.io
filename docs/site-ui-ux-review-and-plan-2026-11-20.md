# Saujana site UI and UX review and improvement plan

20 November 2026 · Repository revision `d39a78d`

Keep Saujana’s paper, green and brass palette, Playfair headings, community photography and activity illustrations. The current site generally gives visitors a clear way into each activity. The largest gains are making organiser work easier to find and safer to leave, then tightening how public pages guide people from a date, game or score to their next action.

## Implementation order

1. **Repair navigation and prevent lost work.** Fix the Home anchor and use document order to place the tournament’s next action and section navigation before the work sections. Make section jumps update the fragment and focus the destination heading. Give sign-in, authenticator retry and post-login destinations deliberate focus. Reuse the existing draft-discard checks for explicit sign-out on editing pages, offering the organiser a way to stay and save before leaving. Keep these fixes small enough to ship independently of visual changes.
2. **Make the organiser workspace faster on phones.** Pilot a compact header and a labelled module menu with a current-page indicator and a skip link. Surface the first dashboard destination within 320 × 568 with the default text size. Give Riichi Open a stage-aware entry point and Clocktower a clear capture, review and publish sequence. Put recoverable errors beside the affected edit. Finish with the smaller Birthday Club and Visitor names changes once the common organiser layout is stable.
3. **Make public journeys easier to follow.** Align event facts and action labels across Home, Gatherings and Clocktower. Bring archive search, filters and reset into a predictable order. Refine the Riichi section around the tasks people came to do, and check Birthday Club consent from the public form through the organiser’s agenda. Reuse existing components and styles where the same interaction has the same meaning.
4. **Validate the dense states before release.** Extend the existing responsive checks with a small set of fixture journeys that verify focus, recovery and publication state. Compare the first screen and the primary task on desktop and a short phone, then run keyboard and real-device checks.

## Shared UI patterns

- Use one primary action per decision, with the terms or consequences beside it. Reuse the existing status styles and keep save, retry and validation messages near the controls they describe. Use text labels alongside colour for payment, publication and consent states. [Shared styles](../app/assets/css/main.css)
- Keep illustrations and larger display type on public discovery pages. In the organiser workspace, use a compact sans-serif hierarchy for forms, tables and status with display type reserved for page headings. Keep repeated controls and essential metadata at least 14 px, and use tabular figures for dates and scores. Preserve the Clocktower accent on its own pages. [Site conventions](../CODEX.md) · [Organiser layout](../app/layouts/admin.vue)
- Keep operations with different consequences visually distinct. Give a private draft save inline feedback. Show the record, outcome and public visibility in the final review for actions such as round certification or recap publication. [Tournament organiser](../app/pages/admin/riichi-open.vue) · [Clocktower organiser](../app/pages/admin/only-blood-in-the-clocktower.vue)

## Release checks

- **Task completion.** Run the Home to gathering sign-up, Collection to Play History and back, shared Clocktower recap, Calculator score, League submission, Birthday Club consent and Riichi Open receipt flows. Run all five organiser destinations with populated test data. Verify the hard-to-reverse actions by inspecting both the organiser state and its public counterpart where applicable.
- **Keyboard and mobile.** Check 320 × 568, 390 × 844, landscape, tablet and desktop. Test at 200% zoom, in reduced motion, and with the native keyboard open. Keep focus visible and correctly placed after jumps, dialog closure, validation and sign-in. Use 44 CSS px as the target for frequent touch actions and check WCAG 2.2 AA focus, contrast, naming and status messages. Verify VoiceOver on iOS and TalkBack on Android for sign-in, sign-up, score entry and publication. [W3C WCAG 2.2 quick reference](https://www.w3.org/WAI/WCAG22/quickref/)
- **Regression.** Run static generation, SEO, responsive verification and the existing unit tests for implementation changes. Add fixture assertions for the Home anchor, tournament section order and focus, dirty sign-out and authenticator retry because a layout-width check cannot detect them. Confirm that admin pages retain their `noindex` tags and remain outside the public sitemap. [SEO checks](../scripts/verify-seo.mts) · [Responsive checks](../scripts/verify-responsive.mjs)
